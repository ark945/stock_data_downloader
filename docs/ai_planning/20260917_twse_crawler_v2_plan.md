# 全新一代 TWSE 券商買賣日報表爬蟲架構規劃 (v2)

舊版爬蟲在 2026-09-17 盤後全市場執行中遭遇嚴重瓶頸：
1. **0.3s 極限速度連續發送上千次請求，觸發站方「靜默限流（Silent Drop）」**：伺服器回傳長度僅 236 bytes 的空白 HTML 頁面。
2. **缺乏限流感知與熔斷冷卻**：程式將空白頁視為普通失敗持續盲打，導致 IP 被持續鎖死，後續數百檔全部失敗。
3. **無原生斷點續傳**：一旦中途中斷，進度無法無縫銜接，重複浪費請求額度。

本規劃徹底捨棄舊版歷史包袱，專注於開發強韌、高可用、具備限流感知與斷點續傳的全新一代獨立模組 **`twse_crawler_v2.py`**。

## 2. 核心特性明細

### 2.1 熔斷冷卻器（Circuit Breaker）
* **觸發條件**：
  - POST 回應長度 `< 500 bytes`（例如 236 bytes 的空白 HTML）。
  - 或 HTTP 回傳 403 Forbidden / 429 Too Many Requests。
* **行為機制**：
  - 連續 2 次偵測到上述特徵時，爬蟲立即暫停佇列。
  - 於終端顯示冷卻倒數計時器（預設冷卻 60～90 秒）。
  - 冷卻倒數結束後，主動發送 1 檔輕量測試探針；確認站方已正常產出下載按鈕後，自動接續佇列，徹底避免無腦盲打將 IP 鎖死。

### 2.2 原生斷點續傳（Checkpointing）
* 成功抓取一檔即刻將原始數據暫存至 `output/.checkpoint_twse_v2_{DATE}/`。
* 狀態檔記錄已完成標的代碼。
* 使用者隨時可按 `Ctrl + C` 終止；再次啟動時**自動跳過已完成標的**，達到 0 秒接續。

### 2.3 自適應節奏控制（Adaptive Pacing Engine）
* **全市場模式**：
  - 延遲設定在 1.0s ~ 1.5s 隨機浮動，模擬真人瀏覽特徵。
  - 批次呼吸：每採集 50 檔自動微休 3～5 秒。
* **定向/補跑模式**（標的數少於 50 檔）：
  - 自動啟用敏捷模式（0.6s ~ 0.8s 延遲）。

### 2.4 完全相容的資料格式
* 下載解析後的資料結構與產物檔名完全相容：
  - `output/api_absr1_{DATE}_{DATE}.parquet`
  - `output/api_absr1_{DATE}_{DATE}.xlsx`
* 欄位定義完全對齊現有系統：
  - `股票代號`, `證券名稱`, `日期`, `券商代號`, `券商名稱`, `價格`, `買進股數`, `賣出股數`。

## 3. CLI 介面設計

```bash
# 1. 全市場斷點採集（預設自動跳過已完成標的）
python twse_crawler_v2.py --date 2026-09-17

# 2. 定向採集/補抓指定標的
python twse_crawler_v2.py --date 2026-09-17 --symbols 2330,2317,2454

# 3. 指定自訂安全延遲
python twse_crawler_v2.py --date 2026-09-17 --delay 1.5
```
