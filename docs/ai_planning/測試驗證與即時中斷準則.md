# CI/CD 雲端分片測試驗證與即時中斷準則

## 1. 核心原則：極速失敗與即時攔截 (Fast-Fail & Real-Time Interception)
* **嚴禁被動等待**：當雲端排程啟動後，禁止呆等 20 分鐘跑完全部節點才開始看結果。
* **前 1~3 檔即時驗證機制**：
  - 任務啟動 30~60 秒內，必須主動抽檢前 3 個分片的首 3 檔標的日誌。
  - 若偵測到連續 2 檔出現 `[API 封包逾時]`、`[TPEX 操作逾時]` 或 `[真人驗證阻擋]`，**即刻判定為系統性問題，立刻進行代碼定位與修復，絕不浪費時間等待後續無效執行**。

---

## 2. 品質門禁與紅叉判定標準 (100% 成功鐵律)
1. **單一失敗即紅叉 (Zero Failure Tolerance)**：
   - 任何分片中只要有 **1 筆** 股票採集失敗，該分片在 Python 層必須直接拋出 `RuntimeError` 退出（Exit Code 1）。
   - GitHub Actions 必須明確亮紅叉（Failed），嚴禁在有失敗標的情況下顯示綠勾（Success）。
2. **20 分鐘硬性時限 (Timeout Constraint)**：
   - 每個分片（50 檔）執行時間嚴格限制在 20 分鐘內。
   - 本地單檔採集標準為 1~5 秒/檔，全分片 50 檔應於 3~7 分鐘內高速完成。超時即視為死鎖或封鎖失敗。
3. **無效產物禁止偽裝**：
   - 若分片未產出任何有效資料（0 筆成交且有失敗），禁止靜默 return，必須拋出異常標記失敗。

---

## 3. TPEX 核心表單與事件規範
1. **精準表單定位**：
   - 全域 `document.querySelector('form')` 會誤取頂部搜尋列 (`search.html`)。
   - 必須嚴格鎖定 `form.formblock` 或 `form#tables-form` 內部的查詢按鈕 `form.formblock button[type="submit"]`。
2. **事件觸發保證**：
   - TPEX 官方採用 jQuery 按鈕點擊監聽，必須使用 `q_btn.click()` 或 `$('form.formblock button[type="submit"]').click()` 觸發 AJAX，嚴禁使用無效的 `form.requestSubmit()` 繞過按鈕事件。
3. **Token 一次性防重用**：
   - 每次換檔必須清空 `input[name="cf-turnstile-response"]` 並強制等待相異全新 Token。
